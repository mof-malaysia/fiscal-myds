## Purpose

### Move a task forward

A button commits the user to something: continuing to the next step, submitting a form, paying. The label says exactly what will happen.

### Make the next step obvious

A screen has one primary button, so the way forward is never in doubt. Everything else is quieter.

### Confirm a serious action

Danger buttons are kept for the final step of something that can't easily be undone, such as deleting a record.

## Configuration

### Variant

Eight variants in three tones. Use **Primary** for the one main action on a screen, **Secondary** for other actions beside it, and **Tertiary** for low-emphasis actions in toolbars and rows. The colour versions add MYDS Blue where an action needs a little more pull without competing with Primary. **Danger** variants are for destructive actions.

<Example code={variantCode}>
  <Variant client:visible />
</Example>

| Variant          | `variant` value   | Use for                                          |
| ---------------- | ----------------- | ------------------------------------------------ |
| Primary          | `primary-fill`    | The main action on the screen. Only one.         |
| Secondary        | `default-outline` | Other actions next to the primary, like Back.    |
| Secondary colour | `primary-outline` | A secondary action that should stand out a bit.  |
| Tertiary         | `default-ghost`   | Low-emphasis actions in toolbars and table rows. |
| Tertiary colour  | `primary-ghost`   | Low-emphasis actions that need a hint of colour. |
| Danger primary   | `danger-fill`     | The final confirmation of a destructive action.  |
| Danger secondary | `danger-outline`  | A destructive action that isn't the last step.   |
| Danger tertiary  | `danger-ghost`    | Destructive actions in rows and menus.           |

### Size

Three sizes, each relative to the density. Use **Small** for most buttons, **Medium** where the button is the focus of a section, and **Large** for a single call to action on a landing page. Switch the density above the preview to see how sizes change.

<Example code={sizeCode}>
  <Size client:visible />
</Example>

### State

Buttons have default, hover, focus and disabled states. Hover deepens the fill over 150ms, and focus adds a 2px Focus Blue ring offset 2px from the button. Pressing nudges the button down by half a pixel. Disabled buttons lighten and stop responding.

<Example code={stateCode}>
  <State client:visible />
</Example>

### Leading and trailing icon

A **leading icon** sits before the label and hints at the action, like download or delete. A **trailing icon** sits after it and suggests direction, like an arrow to the next step.

### Icon only

For familiar actions where space is tight, such as delete in a table row. The icon must be universally understood, and the button still needs a text label for screen readers.

## Structure

Height and padding come from the density, so the same button fits a citizen form or an officer's table.

| Size   | Comfortable (height / padding) | Compact (height / padding) | Label |
| ------ | ------------------------------ | -------------------------- | ----- |
| Small  | 44px / 16px                    | 32px / 12px                | 14px  |
| Medium | 48px / 20px                    | 36px / 14px                | 14px  |
| Large  | 56px / 24px                    | 40px / 16px                | 16px  |

Icon-only buttons are square at the same height. The corner radius is 8px, the label is weight 500, and the gap between icon, label and counter is 6px.

## When to use

- To submit a form or move to the next step of a task.
- To save, confirm or cancel a change.
- To start an action on the current page, like opening a dialog or applying filters.

## When not to use

- To go to another page. Use a link, so people can open it in a new tab and know where it leads.
- For a choice between options. Use radios, checkboxes or a toggle.
- For actions that aren't available. Hide them, or explain what's needed to make them available, instead of showing a disabled button with no reason.

## Built-in accessibility

- Renders a native `<button>`, so it is announced as a button and works with the keyboard without extra code.
- The label on Primary meets 5.2:1 contrast on MYDS Blue, and every variant meets WCAG AA in both themes.
- The focus ring is solid Focus Blue, offset 2px, and measures 4.0:1 against the page.
- In comfortable density, small buttons are 44px tall, which meets the WCAG 2.5.5 target size. Compact buttons are 32px, above the 24px minimum in WCAG 2.5.8.
- Disabled buttons use the `disabled` attribute, so assistive technology reports them as unavailable.

## Labels and content

- Give every icon-only button an `aria-label` that names the action, such as "Delete file".
- When a button has a counter, make sure the label still makes sense read aloud. "Filter 5" may need an `aria-label` like "Filter, 5 applied".
- Keep the visible label in the accessible name. If you add an `aria-label`, start it with the visible text.
- Don't rely on colour alone. A danger button's label should say what will be destroyed.

## Focus and interaction

- Disabled buttons can't be focused, so keyboard and screen reader users may not find them. Say nearby what's needed to enable the action.
- After an action opens a dialog, move focus into it. When it closes, return focus to the button.
- Use `type="submit"` only for the button that submits its form. Other buttons in a form should be `type="button"`.

## Keyboard interaction

| Key       | Interaction                      |
| --------- | -------------------------------- |
| Tab       | Moves focus to the next button.  |
| Shift+Tab | Moves focus to the previous one. |
| Enter     | Activates the focused button.    |
| Space     | Activates the focused button.    |
